## tl;dr

- Spannerに小〜中規模のCSVファイルを手早くインポートするツールとして、[spanner-migration-tool](https://github.com/GoogleCloudPlatform/spanner-migration-tool)やラッパーコマンドの `gcloud alpha spanner databases import` が利用できます[^1]。
- CSVの日付フォーマット変換やカラム抽出などの前処理をSQLで行いながらインポートしたい場合は、BigQueryのReverse ETL（`EXPORT DATA ... format='CLOUD_SPANNER'`）を経由する方法も便利です。
- 数十GiB以上の大規模なCSVデータや定常的なバッチパイプラインでは、Dataflowテンプレートを利用します。

## はじめに

SpannerにCSVファイルをインポートする方法として、マニュアルには[Dataflowを使った方法](https://docs.cloud.google.com/spanner/docs/import-export-csv?hl=ja)や、[BigQueryのReverse ETLを使ったサンプルデータの読み込み方法](https://docs.cloud.google.com/spanner/docs/load-sample-data?hl=ja)が紹介されています。

しかし、Dataflow自体のスピンアップにはある程度の時間がかかるため、開発環境でワンタイムで小規模なCSVファイルをインポートするにはやや大げさである場合があります。そのような場合に、Goで書かれた `spanner-migration-tool` というツールを使うと手元のCSVファイルをコマンド1つで素早く投入できます。

2026年現在における主な3つの手法の使い分けは以下の通りです。

| 手法 | 向いている規模・用途 | スピンアップ時間 | 特徴・考慮点 |
| :--- | :--- | :--- | :--- |
| `spanner-migration-tool` / `gcloud alpha spanner databases import` | 小〜中規模（100GiB未満）のワンタイム投入 | なし（即時実行） | クライアントから直接Spannerへ書き込むため手軽で高速。`TIMESTAMP` 型の書式（`YYYY-MM-DD HH:MM:SS`）に制約あり |
| BigQuery Reverse ETL（`bq load` + `EXPORT DATA`） | 小〜中規模、CSVの型変換やカラム整形を挟みたい場合 | 数秒〜数十秒（サーバーレス） | `bq load` で柔軟に取り込み、`SELECT` クエリーで加工してSpannerへ直接出力可能（要BigQuery Enterprise以上の予約） |
| Dataflowテンプレート（`GCS_Text_to_Cloud_Spanner`） | 大規模データ、定常バッチ取り込み | 数分（ワーカー起動） | GCS上のCSVを並列ワーカーで高速にロード可能。ヘッダー行を含められない制約やネットワーク設定の考慮が必要 |

## spanner-migration-toolとは

[spanner-migration-tool](https://github.com/GoogleCloudPlatform/spanner-migration-tool)（以下、SMT）とは、各種データベースからの移行についての評価とデータの移行を行うツールです。2026年11月時点の対応データベースは以下の通りです。

- PostgreSQL
- MySQL
- SQL Server
- Oracle
- Cassandra

これらに加えて、CSVファイルからテーブルへのインポートにも対応しています。SMTは100GiBより小さいデータベースの移行を想定しているツールです。今回はこのインポート機能を使ってCSVをSpannerにインポートしてみます。

SMTは `gcloud` CLIのコンポーネントとして提供されており、以下のコマンドでインストールできます（Cloud ShellなどのDebian系環境では `sudo apt-get install google-cloud-sdk-spanner-migration-tool` で導入します）。

```sh
gcloud components install spanner-migration-tool
```

## 準備

`spanner-migration-tool data` コマンドでCSVをインポートする場合、あらかじめ移行先のテーブルを定義しておく必要があります。今回は以下のようなテーブルを事前に作成しておきました。

```sql
CREATE TABLE `item` (
        `id` INT64 NOT NULL,
        `name` STRING(10),
        `description` STRING(30),
        `price` INT64,
        `created_at` TIMESTAMP,
) PRIMARY KEY (`id`);
```

インポートするデータのサンプル（`item.csv`）は以下の通りです。

```csv
1,aaaa,bbbbbb,1000,2022-10-27 07:46:56
2,aaaa,bbbbbb,1000,2022-10-27 07:48:32
3,aaaa,bbbbbb,1000,2022-10-27 07:48:34
4,aaaa,bbbbbb,1000,2022-10-27 07:48:34
6,aaaa,bbbbbb,1000,2022-10-27 07:48:35
```

その他、Spanner自体へのアクセス権限や、Cloud Storage（以下、GCS）からファイルを読み込む場合にはその権限を準備してください。

## 実行

CSVファイルのインポートには、テーブルとCSVファイルの対応関係を記述したマニフェストファイルを指定する場合と、指定しない場合の2種類があります。

マニフェストファイルを指定しない場合は、カレントディレクトリにある `<テーブル名>.csv`（今回の例では `item.csv`）を自動的に探してインポートします。手元のCSVを1つのテーブルへ投入するだけであれば、以下のコマンドが最も手軽です。

```sh
spanner-migration-tool data -source=csv \
  -target-profile="instance=インスタンス名,dbName=DB名"
```

ファイルパスを明示したい場合や、NULL扱いする文字列（`nullStr`）を指定したい場合は、`-source-profile` でマニフェストファイルなどを与えます。なお、PostgreSQL方言のデータベースへインポートする場合は `-target-profile` に `,dialect=postgresql` を追加してください。

```sh
spanner-migration-tool data -source=csv \
  -source-profile="manifest=manifest.json,nullStr=NULL" \
  -target-profile="instance=インスタンス名,dbName=DB名"
```

マニフェストファイルのサンプルは以下の通りです。

```json:manifest.json
[
    {
      "table_name": "item",
      "file_patterns": [
              "gs://バケット名/item.csv"
      ]
    }
]
```

例ではGCS上のファイル（`gs://...`）を指定していますが、ローカルのファイルパスを直接指定することも可能です。GCSのファイルを指定した場合、実行時にローカルの `TMPDIR` 配下へ一時ダウンロードして処理するため、ローカルストレージに十分な空き容量があるか注意してください。

また、1テーブル・1ファイルのインポートであれば、ラッパーコマンドの `gcloud alpha spanner databases import` も利用できます。こちらは[スキーマ定義JSONファイル](https://docs.cloud.google.com/sdk/gcloud/reference/alpha/spanner/databases/import#--schema-uri)（`--schema-uri`）の指定が必須となる代わりに、移行先テーブルが未作成でも自動作成され、GCSから一時ファイルを作らず直接ストリーミングで読み込めます。

```sh
gcloud alpha spanner databases import \
  --instance=インスタンス名 \
  --database=DB名 \
  --table-name=item \
  --source-format=csv \
  --source-uri=gs://バケット名/item.csv \
  --schema-uri=schema.json
```

## 注意点

### ヘッダー行とカラム順序

CSVの1行目がインポート先テーブルのカラム名一覧と一致する場合はヘッダー行とみなされ、一致しない場合は1行目からデータ行（テーブル定義のカラム順）として処理されます。

### 日付形式

[ドキュメント](https://github.com/GoogleCloudPlatform/spanner-migration-tool/blob/master/sources/csv/README.md#csv-file-format)にはタイムスタンプはISO 8601を受け取るとありますが、[実装](https://github.com/GoogleCloudPlatform/spanner-migration-tool/blob/master/sources/csv/data.go#L587-L593)を見る限り `strftime("%Y-%m-%d %H:%M:%S")` 形式の文字列のみを受け取ります。`T` やタイムゾーン（`Z` など）が含まれているとエラーになるため、事前に変換するか後述のBigQuery Reverse ETLを利用してください。

### NULLの取り扱いについて

CSVにはRDBのNULLに当たる概念がないため、デフォルトでは空文字列（`,,`）をNULLとして取り扱います。特定の文字列をNULL扱いしたい場合には、`spanner-migration-tool data` の `-source-profile` 引数として `nullStr` を指定してください。前述の例では `NULL` という文字列をNULL扱いするように指定しています。

### プライマリキー重複時の挙動

SMTは内部で `Insert` ミューテーションを発行するため、同一プライマリキーの行がすでに存在する場合は `AlreadyExists` エラーとなりスキップされます。既存行を上書き（Upsert）したい場合は、レコードを削除してから再実行するか、BigQuery Reverse ETLやDataflowテンプレートを利用してください。

### エラーログとドロップされた行の確認

実行時の詳細ログ（デフォルトで `DEBUG` レベル）はカレントディレクトリの `spanner-migration-tool.log` に出力されます。また、型変換エラーなどで取り込めなかった行はスキップされて `<DB名>.dropped.txt` および `<DB名>.report.txt` に記録されるため、実行後に確認してください。

### インポート速度

1,000PU（1 node）のSpannerに対して、上記のサンプルテーブルへ100万行のCSVファイルをインポートしたところ、10〜12秒程度で実行完了しました。

## 別解：BigQuery Reverse ETLを使ったCSVインポート

CSVのタイムスタンプがISO 8601形式（`2026-11-14T07:46:56Z` など）になっていて事前変換の手間を省きたい場合や、一部のカラムだけをSQLで加工して投入したい場合は、BigQueryの `bq load` と[Reverse ETL（`EXPORT DATA`）](https://docs.cloud.google.com/bigquery/docs/export-to-spanner?hl=ja)を組み合わせる方法が便利です。なお、この機能の利用にはBigQueryの予約（Enterpriseエディション以上）が必要であり、オンデマンド課金では実行できない点に注意してください。

手順はシンプルで、まず `bq load` でCSVを作業用テーブルへ読み込み、続いて `EXPORT DATA` 文（`format='CLOUD_SPANNER'`）で `SELECT` 結果をそのままSpannerへ書き出します。

```sh
# 1. 作業用データセットを作成し、CSVをBigQueryへロード
# ※CSVの1行目にヘッダー行がある場合は、末尾のスキーマ指定を省略して --autodetect のみで実行可能
bq mk work_dataset
bq load \
  --source_format=CSV \
  --allow_quoted_newlines \
  work_dataset.item_staging \
  ./item.csv \
  id:INT64,name:STRING,description:STRING,price:INT64,created_at:TIMESTAMP

# 2. BigQueryからSpannerのitemテーブルへエクスポート（SELECTのカラム名をSpanner側と一致させる）
bq query --use_legacy_sql=false '
EXPORT DATA OPTIONS(
  uri="https://spanner.googleapis.com/projects/プロジェクトID/instances/インスタンス名/databases/DB名",
  format="CLOUD_SPANNER",
  spanner_options="""{ "table": "item" }"""
) AS
SELECT id, name, description, price, created_at
FROM work_dataset.item_staging;'
```

`SELECT` 句の中で `PARSE_TIMESTAMP` や `CAST`、`WHERE` によるフィルタリングなどのSQL処理をそのまま記述できるため、CSVファイルを事前加工するスクリプトを書く必要がなくなります。

[^1]: このツールは2023年7月までHarbourBridgeと呼ばれていましたが、`spanner-migration-tool` に改称されました。
