## tl;dr

- Cloud Spannerへ小規模なCSVファイルやMySQL・PostgreSQLのダンプファイルを取り込む手段として、Google Cloudコンソールの「独自のデータをインポート（Import my own data）」および`gcloud alpha spanner databases import`コマンドが利用できます。
- 以前のようにGo言語の実行環境や`spanner-migration-tool`のバイナリを手動でセットアップしたり、マニフェストファイルを記述したりする必要がありません。
- CSVの場合はカラム定義を記述したJSONファイルを添えることで、テーブルの新規作成とデータ投入をまとめて実行できます。

## はじめに

Cloud SpannerにCSVファイルをインポートする公式の手順として、マニュアルには[Dataflowを使った方法](https://cloud.google.com/spanner/docs/import-export-csv?hl=ja)が紹介されています。しかし、Dataflow自体のスピンアップにある程度の時間がかかるため、開発環境においてワンタイムで小規模なCSVファイルをインポートするにはやや大げさである場合があります。

そのため以前の記事[「Cloud SpannerへCSVファイルをインポートする方法」](https://zenn.dev/google_cloud_jp/articles/e72624a106e425)では、Dataflowの代わりにGo製のCLIツールである`spanner-migration-tool`（旧称Harbourbridge）をローカル環境やGCEインスタンスに導入し、マニフェストファイル（JSON）を書いてCSVを取り込む手順を紹介しました。

その後、Google Cloudコンソールおよび`gcloud` CLIの機能拡張により、ツールの手動インストールやマニフェストファイルの準備を意識することなく、CSVファイルやMySQL・PostgreSQLのダンプファイル（`mysqldump` / `pg_dump`）を直接Cloud Spannerへ取り込めるようになりました[1][2]。

本稿では、まずこの新しいインポート機能の全体像と他の手法との位置づけを整理した上で、事前準備、コンソール画面からの実行手順、および`gcloud` CLIから直接実行する手順を順番に解説します。

## インポート機能の全体像と仕組み

具体的な手順に入る前に、このインポート機能が裏側でどのように動作しているのか、そして既存のインポート手法とどう使い分けるのかという大枠を整理します。

### コンソール画面とgcloud CLIの関係

今回紹介する機能には、Google Cloudコンソールの画面から操作する「独自のデータをインポート（Import my own data）」と、コマンドラインから実行する`gcloud alpha spanner databases import`の2つの入り口があります。

マニュアル（英語版）には、コンソールからインポートを実行した際の動作について以下のような説明がされています[1]。

> Spanner opens the Cloud Shell and populates a command that installs the Spanner migration tool and runs the `gcloud alpha spanner databases import` command.
> （参考訳：SpannerはCloud Shellを開き、Spanner migration toolをインストールして `gcloud alpha spanner databases import` コマンドを実行するコマンドを自動入力します。）

つまり、コンソール画面は「インポートに必要なパラメーターをGUIで選択すると、Cloud Shellを起動して`gcloud alpha spanner databases import`コマンドを自動入力してくれるウィザード」として機能します。また、その`gcloud`コマンドの内部では`spanner-migration-tool`が自動的に呼び出され、テーブル作成とデータの書き込みが行われます。

したがって、どちらの入り口を使っても裏側で行われる処理は同じです。
- ブラウザ上のガイドに沿ってファイルを選び、そのままCloud Shell上で実行したい場合はコンソール画面からの操作
- 手元のターミナルやスクリプトから直接コマンドを実行したい場合は`gcloud` CLIからの操作

という形で、作業環境に合わせて選ぶことができます。

### 対応フォーマットとスキーマ定義JSONの役割

この機能では、取り込み元のファイル形式（`--source-format`）として`csv`、`mysqldump`、`pgdump`の3種類に対応しています。ここで特徴的なのは、`mysqldump`や`pgdump`ではダンプファイル1つを指定するだけでインポートできるのに対し、`csv`の場合だけ別途スキーマ定義JSONファイル（`--schema-uri`）の指定が必要になる点です。

この違いは、ファイル自体にテーブルのスキーマ情報が含まれているかどうかによります。MySQLやPostgreSQLのダンプファイルには、データの`INSERT`文だけでなく`CREATE TABLE`文（カラム名、データ型、NOT NULL制約、プライマリキーなどの定義）が最初から含まれています。そのため、ツールはダンプファイルを先頭から解析することで、Cloud Spanner側に対応するテーブルを自動作成してデータを流し込むことができます。

一方で、CSVファイルは単なるカンマ区切りのテキストデータであり、たとえ1行目にヘッダー（カラム名）が含まれていたとしても、「どのカラムが整数型でどのカラムが文字列型か」「どのカラムがプライマリキーか」という型や制約のメタデータを持っていません。そのため、CSVからテーブル作成とデータ投入を一気通貫で行わせるには、カラムの型や主キー順序を明示した軽量なJSONファイルを添えてあげる必要があります。

### 既存のインポート手法との比較・使い分け

現在Cloud SpannerへCSVやダンプデータを取り込む主な手段を整理すると以下のようになります。

| 比較項目 | コンソール画面<br>（独自のデータをインポート） | gcloud CLI<br>（`gcloud alpha spanner databases import`） | Dataflowテンプレート<br>（`GCS Text to Cloud Spanner`） |
| :--- | :--- | :--- | :--- |
| 手軽さ | 手軽（ブラウザ操作とCloud Shellで完結） | 手軽（コマンド1行で実行可能） | やや手間がかかる（ワーカー起動時間やIAM・ネットワーク設定が必要） |
| 対応フォーマット | CSV、MySQLダンプ、PostgreSQLダンプ | CSV、MySQLダンプ、PostgreSQLダンプ | CSV、Avro |
| 想定データ規模 | 小〜中規模（100GiB未満の目安） | 小〜中規模（100GiB未満の目安） | 大規模（100GiB超〜テラバイト級） |
| 主な用途 | ブラウザ上でファイルを選択して手軽にデータを取り込みたい場合 | ローカル端末からの直接実行や、CI/CD・検証環境構築スクリプトへの組み込み | 本番環境への大規模データ移行、高並列なバルクロード処理 |

開発環境でのちょっとしたCSV投入やダンプファイルの取り込みであれば、まずはコンソール画面または`gcloud` CLIを使うのが手軽です。一方で、100GiBを超えるような大規模データの本番移行では、単一マシンで動作するCLIツールでは時間がかかるため、引き続きDataflowによる高並列バルクロードを選択してください。

## 準備

ここからは具体的な手順に入ります。コンソール画面から実行する場合でも、`gcloud` CLIから実行する場合でも、事前のファイル準備は共通です。

今回は例として、ECサイトなどでよく見られるユーザー情報（`users`テーブル）と注文履歴（`orders`テーブル）のCSVファイルをCloud Spannerへインポートします。手元でCSVファイルとスキーマ定義JSONファイルを作成し、Cloud Storage（以下、GCS）のバケットへ配置します。

### サンプルCSVファイルの作成

手元の環境で以下の2つのCSVファイルを作成します。1行目はカラム名を示すヘッダー行として記述します。

`users.csv`
```csv
user_id,name,email,created_at
usr-001,Taro Yamada,yamada@example.com,2026-01-15T09:00:00Z
usr-002,Hanako Sato,sato@example.com,2026-02-01T10:30:00Z
usr-003,Ichiro Suzuki,suzuki@example.com,2026-03-10T14:15:00Z
```

`orders.csv`
```csv
order_id,user_id,amount,status,ordered_at
ord-1001,usr-001,15000,COMPLETED,2026-04-01T11:00:00Z
ord-1002,usr-001,3200,COMPLETED,2026-04-05T16:45:00Z
ord-1003,usr-002,8900,PENDING,2026-04-10T08:20:00Z
```

### スキーマ定義JSONファイルの作成

CSVの各カラムに対応するデータ型とプライマリキー構成を記述したJSONファイルを用意します[1]。各カラムオブジェクトには以下の4つのフィールドを指定します。

- `name`: カラム名
- `type`: Cloud Spannerのデータ型（`STRING(36)`, `INT64`, `TIMESTAMP`など）
- `notNull`: `NOT NULL`制約をつける場合は`true`、NULLを許容する場合は`false`
- `primaryKeyOrder`: プライマリキーの構成順序。プライマリキー以外のカラムには`0`を指定し、プライマリキーのカラムには`1`から始まる整数を指定します

`users_schema.json`
```json
[
  {
    "name": "user_id",
    "type": "STRING(36)",
    "notNull": true,
    "primaryKeyOrder": 1
  },
  {
    "name": "name",
    "type": "STRING(100)",
    "notNull": true,
    "primaryKeyOrder": 0
  },
  {
    "name": "email",
    "type": "STRING(255)",
    "notNull": true,
    "primaryKeyOrder": 0
  },
  {
    "name": "created_at",
    "type": "TIMESTAMP",
    "notNull": true,
    "primaryKeyOrder": 0
  }
]
```

`orders_schema.json`
```json
[
  {
    "name": "order_id",
    "type": "STRING(36)",
    "notNull": true,
    "primaryKeyOrder": 1
  },
  {
    "name": "user_id",
    "type": "STRING(36)",
    "notNull": true,
    "primaryKeyOrder": 0
  },
  {
    "name": "amount",
    "type": "INT64",
    "notNull": true,
    "primaryKeyOrder": 0
  },
  {
    "name": "status",
    "type": "STRING(20)",
    "notNull": true,
    "primaryKeyOrder": 0
  },
  {
    "name": "ordered_at",
    "type": "TIMESTAMP",
    "notNull": true,
    "primaryKeyOrder": 0
  }
]
```

:::details DDL（CREATE TABLE文）での定義例
上記のJSONファイルで定義したスキーマは、Cloud SpannerのDDL（GoogleSQL）で表すと以下の`CREATE TABLE`文に相当します。あらかじめこれらのDDLでテーブルを作成済みのデータベースに対してCSVデータをインポートすることも可能です。

```sql
CREATE TABLE users (
  user_id STRING(36) NOT NULL,
  name STRING(100) NOT NULL,
  email STRING(255) NOT NULL,
  created_at TIMESTAMP NOT NULL,
) PRIMARY KEY (user_id);

CREATE TABLE orders (
  order_id STRING(36) NOT NULL,
  user_id STRING(36) NOT NULL,
  amount INT64 NOT NULL,
  status STRING(20) NOT NULL,
  ordered_at TIMESTAMP NOT NULL,
) PRIMARY KEY (order_id);
```
:::

### Cloud Storage（GCS）へのアップロード

作成したCSVファイルとスキーマ定義JSONファイルを、作業用のGCSバケット（例: `gs://my-spanner-import-bucket/import/`）へアップロードします。

```sh
gcloud storage cp users.csv users_schema.json orders.csv orders_schema.json \
  gs://my-spanner-import-bucket/import/
```

これで事前のファイル準備は完了です。続いて、コンソール画面からインポートする手順と、`gcloud` CLIからインポートする手順をそれぞれ説明します。

## コンソール画面からインポートを実行する手順

Google CloudコンソールのGUIウィザードを使って、先ほど準備したファイルをインポートする手順です。

### インポート画面を開く

Google CloudコンソールでSpannerのインスタンス一覧ページを開き、対象のインスタンスを選択します。インスタンスの概要画面にある「独自のデータをインポート」をクリックします。

![Spannerインスタンス画面の独自のデータをインポートボタン](/images/csv_import_console_01_button.png)

### ファイルとインポート先データベースの指定

「独自のデータをインポート」の設定パネルが開くので、画面の案内に沿って以下の項目を入力します。

1. ソースの選択: 「ファイル形式」のプルダウンから`CSV ファイル`を選択します。
2. ファイルの場所の選択: `Google Cloud Storage からファイルを選択`を選び、「参照」からGCS上の`gs://my-spanner-import-bucket/import/users.csv`を指定します（`パソコンからファイルをアップロードする`を選んで手元のPCから直接アップロードすることも可能です）。
3. スキーマの選択: 同様に`Google Cloud Storage からファイルを選択`を選び、GCS上の`gs://my-spanner-import-bucket/import/users_schema.json`を指定します。
4. 宛先の選択: 「データベース」のプルダウンで`新しいデータベース`（または既存のデータベース）を選択し、新規作成の場合は「データベース名」（例: `ec_app_db`）を入力します。

![独自のデータをインポートの設定フォーム](/images/csv_import_console_02_form.png)

入力が完了したら、画面下部の「インポート」ボタンをクリックします。

### Cloud Shellでのコマンド実行

「インポート」をクリックすると、ブラウザ画面の下部にCloud Shellが自動的に起動します。ターミナル内には、`spanner-migration-tool`コンポーネントのインストールコマンドと、先ほどフォームで指定した引数がセットされた`gcloud alpha spanner databases import`コマンドが自動入力された状態で表示されます。

```sh
gcloud components install spanner-migration-tool && \
gcloud alpha spanner databases import \
  --instance=test \
  --database=ec_app_db \
  --table-name=users \
  --source-format=csv \
  --source-uri=gs://my-spanner-import-bucket/import/users.csv \
  --schema-uri=gs://my-spanner-import-bucket/import/users_schema.json
```

内容を確認して`Enter`キーを押すと処理が開始され、`users`テーブルの作成とCSVデータの書き込みが実行されます。`orders.csv`についても同様の手順で取り込むことができます。

## gcloud CLIから直接インポートを実行する手順

ブラウザのウィザードやCloud Shellを経由せず、手元のPCのターミナルやCI/CDスクリプトから直接インポートを実行したい場合は、`gcloud alpha spanner databases import`コマンドをそのまま実行します[2]。

### CSVファイルのインポート実行

準備セクションでGCSにアップロードしたファイルパスを指定して、コマンドを実行します。インポート先のデータベース（`ec_app_db`）やテーブル（`users`、`orders`）が存在しない場合は自動的に作成されます。

```sh
# usersテーブルのインポート
gcloud alpha spanner databases import \
  --instance=sample-instance \
  --database=ec_app_db \
  --table-name=users \
  --source-format=csv \
  --source-uri=gs://my-spanner-import-bucket/import/users.csv \
  --schema-uri=gs://my-spanner-import-bucket/import/users_schema.json

# ordersテーブルのインポート
gcloud alpha spanner databases import \
  --instance=sample-instance \
  --database=ec_app_db \
  --table-name=orders \
  --source-format=csv \
  --source-uri=gs://my-spanner-import-bucket/import/orders.csv \
  --schema-uri=gs://my-spanner-import-bucket/import/orders_schema.json
```

CSVに関する主なオプションは以下の通りです。
- `--csv-field-delimiter`: フィールドの区切り文字を指定します（デフォルトはカンマ`,`）。TSVファイルなどを読み込む場合はここでタブ文字を指定します。
- `--csv-line-delimiter`: 改行コードを指定します（デフォルトは改行`\n`）。
- `--database-dialect`: インポート先データベースの言語（Dialect）を指定します。PostgreSQLインターフェースのデータベースへ取り込む場合は`POSTGRESQL`を指定します（デフォルトは`GOOGLE_STANDARD_SQL`）。

### MySQL・PostgreSQLダンプファイルのインポート実行

CSVではなく、MySQLの`mysqldump`やPostgreSQLの`pg_dump`で出力したダンプファイルをインポートする場合は、記述がさらにシンプルになります。前述の通りダンプファイル自体にテーブル名やスキーマ定義が含まれているため、`--table-name`や`--schema-uri`を指定する必要はありません。

```sh
# MySQLダンプファイルをインポートする場合の例
gcloud alpha spanner databases import \
  --instance=sample-instance \
  --database=ec_app_db \
  --source-format=mysqldump \
  --source-uri=gs://my-spanner-import-bucket/import/mysql_dump.sql
```

一覧をみて、以前は手作業でバイナリを配置してマニフェストファイルを書いていた作業が、コマンド1つで素直に実行できるようになっているなと実感いただけるのではないかと思います。

## データの確認

インポート処理が完了したら、データが意図通りに取り込まれているか確認します。Google Cloudコンソールの左メニューから「Spanner Studio」を開き、クエリーエディタで以下のSQLを実行します。

```sql
SELECT 
  u.user_id,
  u.name,
  u.email,
  o.order_id,
  o.amount,
  o.status,
  o.ordered_at
FROM users u
INNER JOIN orders o ON u.user_id = o.user_id
ORDER BY o.ordered_at DESC;
```

実行結果として以下のように`users`テーブルと`orders`テーブルが結合されたレコードが返ってくれば、データ型やタイムスタンプの変換も含めて正常にインポートが完了しています。

| user_id | name | email | order_id | amount | status | ordered_at |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| usr-002 | Hanako Sato | sato@example.com | ord-1003 | 8900 | PENDING | 2026-04-10T08:20:00Z |
| usr-001 | Taro Yamada | yamada@example.com | ord-1002 | 3200 | COMPLETED | 2026-04-05T16:45:00Z |
| usr-001 | Taro Yamada | yamada@example.com | ord-1001 | 15000 | COMPLETED | 2026-04-01T11:00:00Z |

## まとめ

`gcloud alpha spanner databases import`コマンドとコンソールUIの「独自のデータをインポート」の登場により、Cloud SpannerへのCSVファイルやSQLダンプファイルのインポートは以前よりも手軽に実行できるようになりました。

- ブラウザのガイドに沿って進めたい場合はコンソールの「独自のデータをインポート」からCloud Shell経由で実行できる
- 手元のターミナルや自動化スクリプトから実行したい場合は`gcloud alpha spanner databases import`を直接呼び出す
- CSVを取り込む際は、カラム名・型・主キー順序を定義したJSONファイルを添えることでテーブル作成までまとめて行われる
- 100GiBを超える大規模な本番移行では、引き続きDataflowを使ったバルクロードを選択する

開発初期のサンプルデータ投入や移行検証のハードルが下がっていますので、用途に合わせてご活用ください。
