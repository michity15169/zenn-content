## tl;dr

- Cloud Spannerへ小規模なCSVファイルやMySQL・PostgreSQLのダンプファイルを取り込む手段として、Google Cloudコンソールの**「Import my own data（独自データのインポート）」**および**`gcloud alpha spanner databases import`**コマンドが利用できます。
- 以前のようにGo言語の実行環境や`spanner-migration-tool`のバイナリを手動でセットアップしたり、マニフェストファイルを記述したりする必要がありません。
- CSVの場合はカラム定義を記述したJSONファイルを添えることで、テーブルの新規作成とデータ投入をワンストップで実行できます。

## はじめに

Cloud SpannerにCSVファイルをインポートする公式の手順として、マニュアルには[Dataflowを使った方法](https://cloud.google.com/spanner/docs/import-export-csv?hl=ja)が紹介されています。しかし、Dataflow自体のスピンアップにある程度の時間がかかるため、開発環境でワンタイムで小規模なCSVファイルをインポートするにはやや大げさである場合があります。

そのため以前執筆した記事[「Cloud SpannerへCSVファイルをインポートする方法」](https://zenn.dev/google_cloud_jp/articles/e72624a106e425)では、Dataflowの代わりにGo製のCLIツールである`spanner-migration-tool`（旧称Harbourbridge）をローカル環境やGCEインスタンスに導入し、マニフェストファイル（JSON）を書いてCSVを取り込む手順を紹介しました。

その後、Google Cloudコンソールおよび`gcloud` CLIの機能拡張により、**外部ツールの手動インストールやマニフェストファイルの準備を意識することなく**、CSVファイルやMySQL・PostgreSQLのダンプファイル（`mysqldump` / `pg_dump`）を直接Cloud Spannerへ取り込めるようになりました[1][2]。

本稿では、一般的なリレーショナルデータベース（以下、RDB）からのデータ移行や初期データ投入を念頭に置きつつ、この新しいインポート機能の裏側の仕組みと具体的な実行手順を解説します。

## インポート機能の裏側の仕組みと3つのアプローチ

新しいインポート機能（コンソールの「Import my own data」および`gcloud alpha spanner databases import`）について、マニュアルには以下のような説明がされています[1]。

> Spanner opens the Cloud Shell and populates a command that installs the Spanner migration tool and runs the `gcloud alpha spanner databases import` command.

**コンソール画面からインポート対象のファイルやスキーマを指定すると、裏側でCloud Shellが起動して必要なツールの導入から`gcloud alpha spanner databases import`コマンドの実行までを自動で組み立ててくれるイメージです。言い換えると、以前の記事で人間が手作業で行っていた`spanner-migration-tool`のセットアップや引数指定を、`gcloud` CLIとコンソールUIが肩代わりしてくれる動作とも言えます。**

現在Cloud Spannerで利用できる3つのデータインポート手法について、それぞれのアーキテクチャと推奨用途を比較したものが以下の図です。

### なぜCSVのときだけスキーマ定義JSONが必要なのか？

この機能では、ソース形式（`--source-format`）として`csv`、`mysqldump`、`pgdump`の3種類がサポートされています。ここで実装者の気持ちになって考えてみると、なぜ`mysqldump`や`pgdump`ではダンプファイル1つを指定するだけでインポートできるのに、`csv`の場合だけ別途スキーマ定義JSONファイル（`--schema-uri`）の指定が求められるのかが理解しやすいと思います。

MySQLやPostgreSQLのダンプファイルには、データの`INSERT`文だけでなく`CREATE TABLE`文（カラム名、データ型、NOT NULL制約、プライマリキーなどのDDL情報）が最初から含まれています。そのため、インポートツールはダンプファイルを先頭から解析することで、Cloud Spanner側に対応するテーブルを自動作成してデータを流し込むことができます。

一方で、CSVファイルは単なるカンマ区切りのテキストデータであり、たとえ1行目にヘッダー（カラム名）が含まれていたとしても、「どのカラムが`INT64`でどのカラムが`STRING`か」「どのカラムがプライマリキーか」という型・制約のメタデータを持っていません。そのため、CSVからテーブル作成とデータ投入を一気通貫で行わせるには、カラムの型や主キー順序を明示した軽量なJSONファイルを添えてあげる必要があります。

## 準備

ここからは、ECサイトなどでよく見られるユーザー情報（`users`テーブル）と注文履歴（`orders`テーブル）のCSVファイルをCloud Spannerへインポートする手順を確認します。接続やデータ配置の前提として、まずはインポート元のファイルをCloud Storage（以下、GCS）のバケットへ配置するところから始めます。

### サンプルCSVファイルの作成

手元の環境で以下の2つのCSVファイルを作成します。

**`users.csv`**
```csv
user_id,name,email,created_at
usr-001,Taro Yamada,yamada@example.com,2026-01-15T09:00:00Z
usr-002,Hanako Sato,sato@example.com,2026-02-01T10:30:00Z
usr-003,Ichiro Suzuki,suzuki@example.com,2026-03-10T14:15:00Z
```

**`orders.csv`**
```csv
order_id,user_id,amount,status,ordered_at
ord-1001,usr-001,15000,COMPLETED,2026-04-01T11:00:00Z
ord-1002,usr-001,3200,COMPLETED,2026-04-05T16:45:00Z
ord-1003,usr-002,8900,PENDING,2026-04-10T08:20:00Z
```

### スキーマ定義JSONファイルの作成

前述の通り、CSVファイルをインポートする場合は各カラムの名前（`name`）、データ型（`type`）、NULL許容フラグ（`notNull`）、およびプライマリキーの順序（`primaryKeyOrder`）を記述したJSONファイルを用意します[1]。

プライマリキー以外のカラムでは`primaryKeyOrder`に`0`を指定し、プライマリキーを構成するカラムには`1`から始まる連番（複合主キーの場合はその構成順）を指定します。

**`users_schema.json`**
```json
[
  {
    "name": "user_id",
    "type": "STRING(36)",
    "notNull": true,
    "primaryKeyOrder": 1
  },
  {
    "name": "name",
    "type": "STRING(100)",
    "notNull": true,
    "primaryKeyOrder": 0
  },
  {
    "name": "email",
    "type": "STRING(255)",
    "notNull": true,
    "primaryKeyOrder": 0
  },
  {
    "name": "created_at",
    "type": "TIMESTAMP",
    "notNull": true,
    "primaryKeyOrder": 0
  }
]
```

**`orders_schema.json`**
```json
[
  {
    "name": "order_id",
    "type": "STRING(36)",
    "notNull": true,
    "primaryKeyOrder": 1
  },
  {
    "name": "user_id",
    "type": "STRING(36)",
    "notNull": true,
    "primaryKeyOrder": 0
  },
  {
    "name": "amount",
    "type": "INT64",
    "notNull": true,
    "primaryKeyOrder": 0
  },
  {
    "name": "status",
    "type": "STRING(20)",
    "notNull": true,
    "primaryKeyOrder": 0
  },
  {
    "name": "ordered_at",
    "type": "TIMESTAMP",
    "notNull": true,
    "primaryKeyOrder": 0
  }
]
```

### Cloud Storage（GCS）へのアップロード

作成したCSVファイルとスキーマ定義JSONファイルを、作業用のGCSバケット（例: `gs://my-spanner-import-bucket/import/`）へアップロードします。

```sh
gcloud storage cp users.csv users_schema.json orders.csv orders_schema.json \
  gs://my-spanner-import-bucket/import/
```

## 実行

ファイルの準備ができたら、インポートを実行します。`gcloud`コマンドから直接実行する方法と、Google Cloudコンソール画面から実行する方法のどちらでも同じ結果が得られます。

### gcloud CLIから直接実行する場合

手元のターミナルやCI/CDスクリプトから実行する場合は、`gcloud alpha spanner databases import`コマンドを使用します[2]。

まず、`users`テーブルのインポートを実行します。インポート先のデータベース（例: `ec_app_db`）が存在しない場合は自動で作成することも可能です。

```sh
gcloud alpha spanner databases import \
  --instance=sample-instance \
  --database=ec_app_db \
  --table-name=users \
  --source-format=csv \
  --source-uri=gs://my-spanner-import-bucket/import/users.csv \
  --schema-uri=gs://my-spanner-import-bucket/import/users_schema.json
```

続けて、`orders`テーブルも同様にインポートします。

```sh
gcloud alpha spanner databases import \
  --instance=sample-instance \
  --database=ec_app_db \
  --table-name=orders \
  --source-format=csv \
  --source-uri=gs://my-spanner-import-bucket/import/orders.csv \
  --schema-uri=gs://my-spanner-import-bucket/import/orders_schema.json
```

もしCSVファイルでカンマ（`,`）以外の区切り文字（タブなど）を使っている場合は、`--csv-field-delimiter`オプションで指定できます。また、インポート先のCloud SpannerデータベースがPostgreSQLインターフェース（Dialect）である場合は、`--database-dialect=POSTGRESQL`を指定してください（デフォルトは`GOOGLE_STANDARD_SQL`です）。

なお、MySQLのダンプファイル（`mysqldump`）やPostgreSQLのダンプファイル（`pg_dump`）をインポートする場合は、以下のように`--source-format`に`mysqldump`（または`pgdump`）を指定するだけで、スキーマ定義JSONやテーブル名の指定なしにデータベース全体を一括で取り込むことができます。

```sh
# MySQLダンプファイルを直接インポートする場合の例
gcloud alpha spanner databases import \
  --instance=sample-instance \
  --database=ec_app_db \
  --source-format=mysqldump \
  --source-uri=gs://my-spanner-import-bucket/import/mysql_dump.sql
```

### Google Cloudコンソールから実行する場合

コマンドのオプションを調べずにブラウザ画面のガイドに沿って進めたい場合は、Google CloudコンソールのUIから操作できます[1]。

1. Google Cloudコンソールで**Spannerインスタンス一覧**ページを開き、対象のインスタンス（例: `sample-instance`）を選択します。
2. 画面上部またはデータベース作成メニューにある**「Import my own data（独自データのインポート）」**をクリックします。
3. インポート設定画面にて以下の項目を指定します。
   - **File type（ファイル形式）**: `CSV`（または`MySQL dump` / `PostgreSQL dump`）を選択します。
   - **Source file（ソースファイル）**: GCS上のパス（`gs://my-spanner-import-bucket/import/users.csv`）を選択するか、ローカルPCから直接ファイルをアップロードします。
   - **Schema file（スキーマファイル）**: CSVを選択した場合に表示されるため、GCS上のスキーマ定義JSON（`gs://my-spanner-import-bucket/import/users_schema.json`）を指定します。
   - **Destination database（インポート先データベース）**: 新規または既存のデータベース名（`ec_app_db`）を指定します。
4. **「Import（インポート）」**ボタンをクリックします。
5. 画面下部に**Cloud Shell**が自動的に立ち上がり、`spanner-migration-tool`のセットアップと`gcloud alpha spanner databases import`コマンドが入力された状態で表示されます。そのまま`Enter`キーを押すことでインポート処理が開始されます。

一覧をみて、以前は手作業でバイナリを落としてきて環境変数やマニフェストを書いていた作業が、かなり素直に実行できるようになっているなと実感いただけるのではないかと思います。

## 確認とインポート手法の使い分け

インポート処理が完了したら、Google Cloudコンソールの左メニューにある**「Spanner Studio」**を開き、データが意図通りに取り込まれているかクエリーを発行して確認します。

```sql
SELECT 
  u.user_id,
  u.name,
  u.email,
  o.order_id,
  o.amount,
  o.status,
  o.ordered_at
FROM users u
INNER JOIN orders o ON u.user_id = o.user_id
ORDER BY o.ordered_at DESC;
```

実行結果グリッドに`users`テーブルと`orders`テーブルを結合した結果が表示されれば、スキーマ定義とデータ型の変換を含めて正常にインポートが完了しています。

### 3つのインポート手法の使い分けまとめ

現在Cloud Spannerへデータを取り込む際は、データの規模や目的に応じて以下の通り使い分けるのがお勧めです。

| 比較項目 | `gcloud alpha spanner databases import`<br>（コンソール「Import my own data」） | `spanner-migration-tool` CLI<br>（単体バイナリでの直接実行） | Dataflowテンプレート<br>（`GCS Text to Cloud Spanner`） |
| :--- | :--- | :--- | :--- |
| **手軽さ** | **極めて高い**（コマンド1行・UI誘導あり） | 中程度（Goバイナリ導入・manifest作成が必要） | 低い（ワーカー起動時間・IAM/ネットワーク設定が必要） |
| **対応フォーマット** | CSV、MySQLダンプ、PostgreSQLダンプ | CSV、各種RDB直接接続、ダンプファイル | CSV、Avro |
| **想定データ規模** | 小〜中規模（100GiB未満の目安） | 小〜中規模（100GiB未満の目安） | **大規模（100GiB超〜テラバイト級）** |
| **適したユースケース** | 開発・検証環境への初期データ投入、手元のCSVやSQLダンプの素早い取り込み | 異種DBからのスキーマ変換評価、Web UI（SMT）を使った対話的な型・主キー設計の調整 | 本番環境への大規模データ移行、高並列なバルクロード処理 |

- **開発・検証環境や小規模なデータ投入**: まずは本稿で紹介した`gcloud alpha spanner databases import`（またはコンソールの「Import my own data」）を使うのが最も手軽です。
- **既存RDBからの本格的なスキーマ評価**: カラムのデータ型変更やインターリーブ構成への組み替えなどをGUI上で試行錯誤したい場合は、`spanner-migration-tool web`コマンドでローカルWeb UIを立ち上げて評価する使い方が引き続き有効です。
- **大規模な本番データの移行**: データサイズが100GiBを超えるような大規模テーブルのインポートでは、単一マシンで動作するCLIツールでは時間がかかるため、Dataflowテンプレート（またはDatastreamとDataflowを組み合わせた継続的レプリケーション）をご検討ください。

## まとめ

`gcloud alpha spanner databases import`コマンドとコンソールUIの「Import my own data」の登場により、Cloud SpannerへのCSVファイルやSQLダンプファイルのインポートは以前よりも格段に手軽になりました。

- 開発環境でのちょっとしたCSV投入や、`mysqldump` / `pg_dump`からの検証環境構築に最適
- CSVを取り込む際は、カラム名・型・主キー順序を定義したシンプルなJSONファイルを添えるだけでテーブル作成まで自動で実行される
- 100GiBを超える大規模な本番移行では、引き続きDataflowを使ったバルクロードを選択する

開発初期のサンプルデータ投入や移行検証のハードルが大きく下がっていますので、用途に合わせてご活用ください。
